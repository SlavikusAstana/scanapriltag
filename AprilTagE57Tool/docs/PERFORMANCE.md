# Скорость и качество pipeline

## Панорама (ArUco) — три режима

| Режим | `pano_detect_scales` | Время (17×20480, ориентир) | Recall (Smirnoff) |
|-------|----------------------|----------------------------|-------------------|
| **2 — быстро** | `(2,)` | ~5 мин | ~37–42 ID |
| **1 — полное** | `(1,)` | ~13 мин | ~47 ID |
| **1+2 — максимум** | `(2, 1)` | ~18–20 мин | ~48 ID (+редкие только на одном scale) |

- **Scale 2** — JPG уменьшается в 2 раза (≈10240×5120), тайловый ArUco. Быстро, далёкие мелкие теги частично теряются.
- **Scale 1** — полное разрешение pano. Лучше для дальних тегов; дольше в ~2.5×.
- **1+2** — оба прохода, в CSV попадает объединение (при дубликате ID берётся крупнее area на pano). Имеет смысл, если нужен максимум уникальных ID; для Smirnoff выигрыш +1–6 ID к scale 1.

Intensity-панорамы `*_scan.png` **не используются** (0 детекций ArUco).

## Ray-guided pass

**Что делает:** после первого прохода (pano → 3D) есть список fused-тегов с координатами. Для каждой станции, где тег **ещё не** был найден на pano, программа:

1. Берёт известную 3D-точку тега (с другой станции).
2. Строит луч от **позиции сканера** этой станции к этой точке.
3. В LiDAR (row/col + XYZ) ищет точки в угловом конусе → plane-ray intersect → новое наблюдение.

**Зачем:** на Smirnoff сканы **13–17** дали **0** детекций на color pano (теги далеко / мелко на JPG), но LiDAR с другой станции уже «знает» где тег. Ray-guided добавил **+25 наблюдений** на 13–17 (108, 364, 472, 538 и др.) — не новые ID с нуля, а подтверждения с дополнительных станций для fusion.

**Не делает:** не ищет новые ID без pano; не заменяет детекцию на pano.

**Скорость:** второй последовательный проход по 17 E57, загрузка облака (кеш помогает). **+1–3 мин**.

**По умолчанию:** вкл. Отключайте, если нужен только pano-pass.

## Intensity refine

**Что делает:** после `center_from_pano_ray` (луч с pano → LiDAR → 3D) в ROI ±40 cells по row/col строится локальная карта **LiDAR intensity**, на ней снова ArUco. Если тот же `tag_id` найден — 3D пересчитывается по узкому патчу, вес наблюдения ×1.5.

**Зачем задумано:** теоретически mm-уточнение в нативной сетке сканера без VIS parallax.

**На Smirnoff:** ArUco на intensity grid **не декодирует** теги (мало cells, другой контраст). Refine не срабатывает, но цикл ROI+ArUco всё равно выполняется → лишнее время.

**По умолчанию:** выкл. Включайте только если на проекте intensity ROI реально находит теги.

## Рекомендуемые профили

### Быстрый (по умолчанию в GUI: scale 2 + ray-guided, ~6–8 мин)

```
pano_detect_scales = (2,)
ray_guided_pass = True
refine_intensity = False
```

### Только pano, без ray (~5 мин)

```
ray_guided_pass = False
```

### Максимум ID (~20–25 мин, всего на 17 станций)

```
pano_detect_scales = (2, 1)   # или только (1,)
ray_guided_pass = True
refine_intensity = False
```

**20–25 мин** — только режим **1+2** (два прохода ArUco на полной pano) **+** ray-guided, 4 процесса, кеш.  
С **scale 2 + ray** ориентир **~6–8 мин**, не 20–25.
